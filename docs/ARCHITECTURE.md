# Как устроен магазин

Сайт состоит из семи контейнеров, которые запускаются одной командой `docker compose up -d --build`.

| Контейнер | Что делает |
|---|---|
| `nginx` | Принимает запросы из интернета. `/api/...` отправляет бэкенду, остальное фронтенду. Ограничивает частоту запросов с одного адреса. |
| `frontend` | Сайт на Next.js: страницы собираются на сервере и отдаются готовым HTML. |
| `backend` | API на FastAPI: данные магазина, каталог, заказы, коды подтверждения. При старте применяет миграции базы. |
| `worker` | Фоновый воркер Celery: импорт прайсов, уведомления, служебные задачи. |
| `beat` | Планировщик Celery: запускает задачи по расписанию. |
| `db` | База данных PostgreSQL 16. Данные лежат в томе `postgres_data`. |
| `redis` | Redis 7: коды подтверждения, ограничения, кеш и очередь задач. |

## Как контейнеры узнают друг о друге

Внутри Docker у каждого контейнера есть имя: `backend`, `frontend`, `db`, `redis`. Фронтенд ходит к
бэкенду по адресу `http://backend:8000`, бэкенд к базе по адресу `db:5432`. Снаружи открыт только nginx.

## Как проверить, что всё живо

Адрес `/health` (он же `/api/v1/health`) показывает состояние приложения, базы, Redis и фонового воркера. Воркер каждую минуту оставляет
отметку в Redis; если отметки нет дольше трёх минут, страница состояния сообщает об этом.

## Ошибки

Любая ошибка API возвращается в одном формате: `{"error": {"code": "...", "message": "..."}}`, где
сообщение всегда на русском и понятно покупателю. Технические подробности остаются в логах контейнера.
Фронтенд при недоступном бэкенде показывает страницу с предупреждением, а не пустой экран.

## Настройки

Все настройки в файле `.env` (образец `.env.example`). Данные магазина (телефон, адрес, часы, реквизиты)
при первом запуске берутся из `.env`, дальше редактируются в панели управления.

## База данных

Схема создаётся миграциями Alembic (`backend/alembic/versions`), при каждом старте контейнера `backend`
выполняется `alembic upgrade head`. Таблицы: бренды, категории, поставщики, товары и фото, кросс-номера,
справочник автомобилей (марка, модель, поколение, модификация), применяемость, шаблоны VIN, системы и узлы со
схемами и точками, покупатели и гараж, чёрный список, коды подтверждения, заказы с позициями и журналом статусов,
заявки по VIN, зоны доставки, правила наценки, шаблоны и журнал импорта, сотрудники панели, их сессии и журнал действий.

Статусы хранятся строками и проверяются ограничениями базы. Номера заказов идут из последовательности,
начиная с 2401. Для поиска по названию с опечатками включено расширение `pg_trgm` и триграммный индекс.

## Панель управления

Адрес `/admin`. Роли: владелец (всё) и менеджер (без управления сотрудниками). Вход по логину и паролю,
пароли хранятся хешем Argon2id. После входа браузер получает две httpOnly-cookie: короткий токен доступа (JWT,
15 минут) и токен сессии (14 дней). Когда токен доступа истекает, `frontend/src/proxy.ts` тихо обновляет его через
бэкенд, а при недействительной сессии показывает форму входа с кодом ответа 401. Старый токен сессии после
обновления сразу отзывается. Изменяющие запросы по cookie требуют заголовок `X-Requested-With`, это защита от
подделки запросов с чужих сайтов. Попытки входа ограничены: пять неверных паролей в минуту на логин.
Все входы, неудачные попытки и выходы пишутся в журнал действий.
